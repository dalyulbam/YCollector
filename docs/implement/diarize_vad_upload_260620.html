화자 구분 · 무음 분할/배치 가속 · 음원 업로드

전사·요약 분석 보드(패널 ③)를 탐색기식 폴더 네비게이션으로 바꾸고, 그 위에 세 기능을 얹었다 — (A) 화자 구분(diarization) 웹·자동 파이프라인 연동, (B) 무음 분할 민감도 + 배치 가속 노출, (C) 로컬 음원·영상 파일 업로드 전사.

바로가기 · ① 개요 · ② 보드 재설계 · ③ 화자 구분 · ④ 무음 분할·배치 · ⑤ 음원 업로드 · ⑥ 패키지·기술 · ⑦ 트렌드 · ⑧ 검증

1. 개요 — 무엇을, 왜

분석 보드(패널 ③)는 다운로드한 영상/음원을 전사 → 요약 → 장면 앨범북으로 가공하는 곳이다. 이번 변경의 동기:

  • 보드가 지저분했다 — 모든 폴더를 평면으로 쏟아내던 것을 윈도우 탐색기처럼 경로를 따라 한 폴더씩 들어가는 방식으로 재설계.
  • "누가 말하는지" 구분이 필요했다 — 전사 대본에 화자([화자1], [화자2]…) 라벨을 붙이는 화자 구분을 보드 버튼·자동 파이프라인으로 연동.
  • "무음마다 끊어 전사"하면 어떨지에 대한 답 — VAD(무음 구간 검출)는 이미 켜져 있었고, 그 민감도와 배치 가속을 노출해 "안전한 형태의 무음 분할"을 제공.
  • URL·폴더 외에 로컬 음원 파일을 브라우저에서 바로 올려 전사할 수 있게 업로드 UI 추가.

관통하는 설계 원칙: 다운로드(yt-dlp)·전사(GPU)·요약(Claude)·앨범(ffmpeg)에 이어, 화자 구분(ECAPA)도 영속 큐의 단일 소비자 "레인"으로 편입 — 서버가 죽었다 떠도 재시도 가능하고, 무거운 작업이 서로를 막지 않게 분리.

3. (A) 화자 구분 — 토큰 없는 ECAPA diarization

핵심 선택: 게이트 모델 pyannote.audio(HuggingFace 토큰 + 약관 동의 필요) 대신, 공개 speechbrain ECAPA-TDNN 화자 임베딩 + 응집 클러스터링. "이름은 몰라도 화자만 구분"을 토큰 마찰 없이 달성.

파이프라인

전사 산출물 화자 구분(diarize_folder) 대본 재작성 _analysis/*.srt ─┐ _analysis/*.json ─┼─▶ ffmpeg 16kHz mono wav 추출 _analysis/ (JSON 우선, │ ─▶ 세그먼트별 ECAPA 임베딩(192d) ─▶ .script.md 없으면 SRT 파싱) ─┘ ─▶ 코사인 응집 클러스터링(threshold) (원자적 tmp→replace, ─▶ 첫 등장 순 화자1·화자2… 라벨링 화자 라벨 포함)

정방향 체이닝: 전사 → 화자 구분 → 앨범

앨범 렌더러(album.py)는 script.md의 **[h:mm:ss] 화자N:** … 라인을 파싱해 장면별 화자 대화를 싣는다. 그래서 순서를 전사 → 화자 구분 → 앨범으로 고정해 앨범이 화자 라벨을 반영하게 했다. 동시에 같은 script.md를 두 레인이 읽고/쓰는 경쟁을 피하려고 화자 구분 쓰기는 원자적(tmp+replace)으로 처리. 
# 화자 구분 ON: diarize 작업이 끝난 뒤(성공/실패 무관) 앨범을 이어서 enqueue
_run_analyze(make_diarize=True, make_album=True)
   └─▶ _enqueue_diarize(folder, make_album=True)
          └─▶ _run_diarize_task → (ECAPA 실행) → make_album 이면 _enqueue_album(folder)

# 화자 구분 OFF: 종전대로 요약된 폴더를 곧장 앨범 레인으로

회복탄력성: 화자 구분 의존성(torch 등)이 없어 diarize가 not-installed로 실패해도, 앨범 자동화는 잃지 않도록 실패 후에도 앨범을 enqueue하게 했다(검증으로 확인).

4. (B) 무음 분할 민감도 + 배치 가속

"음이 비어있는 순간마다 끊어 전사하면?" 이라는 질문에 대한 정직한 답:

  • faster-whisper의 vad_filter(Silero VAD)는 이미 기본 ON — 무음을 제거해 환각(hallucination)↓·속도↑.
  • "매 pause마다 조각을 독립 전사"하는 건 보통 손해 — Whisper는 직전 텍스트 문맥(condition_on_previous_text)으로 추론하고 30초 윈도우로 학습됐기에, 짧은 파편은 문맥 손실·정확도↓.
  • 그래서 노출한 건 안전한 형태: ① VAD 민감도(무음 길이 임계) ② 배치 가속(VAD 컷을 ~30초로 묶어 배치 추론 — WhisperX가 검증한 방식).
설정 ([transcribe] / 패널 "고급")의미
vad_min_silence_ms이만큼 조용하면 발화 경계로 절단. 작을수록 잘게(표준 2000 · 촘촘 700 · 매우 촘촘 300)
vad_speech_pad_ms음성 구간 앞뒤 여유(ms) — 단어 잘림 방지
vad_threshold음성 판정 임계값(0~1)
batched / batch_sizeBatchedInferencePipeline으로 VAD 컷 배치 추론(VAD 강제 ON) — 긴 파일 대폭 가속
# whisper.py — VadOptions 키로 매핑, 배치는 지연 생성 파이프라인
vad_params = {"threshold": …, "min_silence_duration_ms": …, "speech_pad_ms": …}
if cfg.batched:
    BatchedInferencePipeline(model).transcribe(src, batch_size=…, vad_filter=True, vad_parameters=vad_params)
else:
    model.transcribe(src, vad_filter=cfg.vad_filter, vad_parameters=vad_params)

faster-whisper 1.2.1의 실제 API를 introspect로 확인한 뒤 구현(추측 금지): BatchedInferencePipeline.transcribe(... beam_size, batch_size, vad_filter, vad_parameters, condition_on_previous_text ...), VadOptions 필드 = threshold / min_silence_duration_ms / speech_pad_ms 등.

7. 배경이 된 기술 트렌드

① WhisperX식 "VAD 컷 + 배치 추론"

긴 오디오를 무음(VAD) 경계로 자르고 ~30초 윈도우로 묶어 배치 전사 → 강제 정렬 → 화자 구분. 환각↓·속도↑를 문맥 손실 없이 얻는 정석. faster-whisper의 BatchedInferencePipeline이 이 방식을 라이브러리에 내장 — 본 구현이 노출한 "배치 가속"이 그것.

② 토큰 없는 화자 구분(speechbrain ECAPA) vs 게이트 pyannote

최신 diarization은 pyannote가 강력하지만 HF 토큰·약관 동의라는 마찰이 있다. 화자 임베딩(ECAPA-TDNN) + 단순 군집화는 정확도를 약간 양보하는 대신 토큰 0·즉시 사용 — 로컬 단독 도구에 적합한 트레이드오프.

③ 로컬·인프로세스 ML, 온디바이스 GPU

외부 whisper.exe 호출 대신 in-process 라이브러리, CUDA(블랙웰 RTX 5070 Ti)에서 INT8/FP16 추론, CPU 자동 폴백. 클라우드 API 없이 로컬에서 전사·요약·화자 구분·앨범까지 완결하는 "local-first AI" 흐름.

④ 영속 작업 큐 + 단일소비 레인

GPU(전사)·CPU(앨범 ffmpeg)·ML(화자 구분)을 자원 특성별 레인으로 분리해 동시에 돌리되 각 레인은 1개씩 직렬. 서버 크래시 후 running→interrupted 회복·재시도. 로컬 장시간 ML 배치의 실무 패턴.

8. 검증

스모크 테스트(격리 cwd/APPDATA, lifespan 미기동 → 모델 로드 없음)

  • 백엔드 컴파일 + 라우트 등록(/api/diarize, /api/analyze/upload, /api/queue/scan-diarize …)
  • 업로드: 한글 파일 저장 / .xyz 거부 / spec에 diarize·vad·batched 반영
  • 브라우즈: 폴더·파일 diarized 필드 / 화자✓
  • 화자 구분 엔드포인트·스캔: 의존성 없을 때 400(안내) — DiarizeError(not-installed) 깔끔히 전파
  • 체이닝: diarize 실패해도 앨범 enqueue 보존 / _enqueue_diarize dedup / 전사물 게이팅
  • node --check app.js 통과, _parse_srt/_script_has_speakers 단위 확인

적대적 리뷰(멀티에이전트)

5개 차원(동시성·엔진·보안·프론트·통합) 리뷰 → 발견 검증. 확정 4건 수정: 큐 재시도 라벨 매핑(trackKind), _enqueue_diarize 전사물 검사 TOCTOU(잠금 안으로), batch_size is None 교정. 기각 4건.
