YCollector
구현 기록 · 2026-05-25

FastAPI 공유 백엔드 통일 + 재생목록 전체 다운로드

기존에 분리되어 있던 Tauri sidecar(NDJSON) 백엔드와 FastAPI 서버를 FastAPI 하나로 통일.
동시에, 재생목록 전체 다운로드 토글을 web UI와 React 프론트엔드 양쪽에 구현.

1. 배경: 왜 통일이 필요했나

프로젝트에 두 개의 프론트엔드가 별개로 존재했다:

Tauri + React (5/21~)FastAPI web UI (5/24~)
통신NDJSON sidecar (stdin/stdout)HTTP REST + SSE
진입점src-tauri/ + frontend/src/ycollector/server.py + webui/
Sora 생성미구현지원
설정 UISettingsSheet (17 항목)없음

핵심 문제: 기능 추가 시 양쪽 모두 수정 필요 (코드 중복). 재생목록 토글 추가 시 이 문제가 표면화.

5. 재생목록 전체 다운로드 흐름

사용자 경험

  • URL 입력 바 옆에 토글 버튼 (기본: 「단일」, 클릭 시: 「전체」로 전환 + 보라색 활성화)
  • 「전체」 상태에서 다운로드 시 재생목록의 모든 영상을 받음
  • 설정의 playlist_mode 를 바꾸지 않음 (per-download override)

데이터 흐름

1. [UI] 토글 ON → playlist_mode = "expand"
2. [UI] 다운로드 클릭
3. [HTTP] POST /api/download {url, settings: {playlist_mode: "expand", ...}}
          또는 {url, playlist_mode: "expand"} (web UI 호환)
4. [서버] _run_download() → settings merge → s.playlist_mode == "expand"
5. [서버] yt-dlp --yes-playlist → 재생목록 전체 다운로드

7. 검증

확인된 사항

  • TypeScript 컴파일 통과 (tsc --noEmit)
  • GET /api/settings — 15개 설정 필드 + _source 정상 반환
  • POST /api/download {url, playlist_mode: "expand"} — job 생성 + yt-dlp [youtube:tab] extractor 사용 확인 (= --yes-playlist 동작)
  • SSL 오류는 TLS 가로채기 환경 문제 (코드 문제 아님)
