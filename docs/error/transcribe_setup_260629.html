전사(transcribe) 설치 오류 & HuggingFace 경고 정리

음원·영상 전사를 돌렸더니 [not-installed] faster-whisper 로 막혔고, 설치 후 첫 실행에서 HuggingFace 경고 2개가 떴다. 하나(설치)는 진짜 에러, 둘(HF)은 무해한 경고다. 원인·해결·구분을 정리한다.

1. ERROR faster-whisper 미설치

[not-installed] faster-whisper 가 설치돼 있지 않습니다.
  설치: uv sync --extra transcribe --native-tls
  실행: uv run --extra transcribe ycollector transcribe ...
(import 오류: No module named 'faster_whisper')

원인

  • transcribe extra(= faster-whisper + truststore)가 venv 에 실제로 설치돼 있지 않았다.
  • 헷갈렸던 점: 재생목록 전사(analyze-url)는 다운로드 단계까지는 통과한다(yt-dlp 는 faster-whisper 불필요). 그래서 영상 31개(~4.1GB)는 받아졌지만, 전사 단계에 진입하는 순간 이 에러가 났다.
  • 또 diarize_available: true 였어도 무관 — diarize 와 transcribe 는 별개 extra다.
  • 설치 점검 결과 transcribe 계열이 전부 빠져 있었다(아래). 과거 uv sync --extra <something> 의 prune 흔적으로 보인다(다음 절 참고).
# uv run --no-sync python -c "..."  결과 (모두 없음)
faster_whisper   --- 없음      ctranslate2      --- 없음
av               --- 없음      onnxruntime      --- 없음
tokenizers       --- 없음      huggingface_hub  --- 없음
truststore       --- 없음

해결

uv pip install "faster-whisper>=1.1.0" "truststore>=0.9.0" --native-tls

faster-whisper 가 ctranslate2 / av / onnxruntime / tokenizers / huggingface-hub 등을 끌어와 26개 패키지가 설치됐다(faster-whisper 1.2.1, ctranslate2 4.8.0, av 17.1.0, onnxruntime 1.27.0, truststore 0.10.4, numpy 2.5.0 …).

검증

  • faster_whisper 1.2.1 import OK
  • ctranslate2 4.8.0 import + DLL 로드 OK(= 잘린 휠 아님 — 가로채기 환경의 단골 함정 통과)
  • 서버/CLI 가 쓰는 transcribe.whisper · transcribe.cli import OK
설치 후 서버 재시작 필요. 실행 중이던 서버 프로세스는 import 캐시 때문에 새 패키지를 못 본다. takeover 가 있으니 uv run --no-sync ycollector-server 한 줄이면 기존을 닫고 새로 뜬다(인식됨).

2. 왜 uv sync 가 아니라 uv pip install 인가

에러 메시지는 uv sync --extra transcribe 를 안내하지만, 이 환경에서는 그걸 쓰면 안 된다. 이유 둘:

위험설명
prune 다른 extra 제거 uv sync --extra transcribe 는 env 를 "transcribe + base" 와 정확히 일치시키려 한다 → 지정 안 한 web / video-gen / summarize / diarize 를 지워버린다. (실행 중인 서버의 fastapi/uvicorn 까지 날아갈 수 있음.)
recreate venv 재생성 pyvenv.cfg(3.13.11) ↔ 시스템 Python(3.13.13) 드리프트 때문에 uv sync 가 venv 통째로 재생성을 시도 → 가로채기 네트워크로 전부 재다운로드(잘린 휠 위험) + 서버가 떠 있으면 .venv\Lib 락으로 삭제 실패.

그래서 additive 한 uv pip install — 기존 패키지(web/diarize 등)를 건드리지 않고 faster-whisper 만 더한다. prune 없음, recreate 없음. 가로채기 환경 대응으로 --native-tls 만 붙인다.

transcribe extra 는 이미 pyproject.toml · uv.lock 에 등록돼 있으므로 소스 변경/커밋 불필요 — venv 에 물리적으로 깔기만 하면 된다.

3. WARN HF_TOKEN 미설정 — 무해

Warning: You are sending unauthenticated requests to the HF Hub.
Please set a HF_TOKEN to enable higher rate limits and faster downloads.
  • 공개 모델(mobiuslabsgmbh/faster-whisper-large-v3-turbo)을 익명으로 받는 것이라 토큰 불필요.
  • 토큰은 속도/레이트리밋에만 영향. 모델은 한 번 받으면 캐시되어 재다운로드 없음.
  • 조치: 보통 무시. 반복 요청으로 HTTP 429 가 날 때만 HF_TOKEN 환경변수 설정.
덤: 이 메시지의 모델명이 설정값 [transcribe] model = large-v3-turbo 의 CT2 변환본이다 → 엔진이 제대로 로드돼 모델을 받는 중이라는 정상 신호.

4. WARN Windows 심볼릭 링크 미지원 — 무해

UserWarning: `huggingface_hub` cache-system uses symlinks by default ...
your machine does not support them in C:\Users\user\.cache\huggingface\hub\...
Caching files will still work but in a degraded version that might require more space.
To support symlinks on Windows, activate Developer Mode or run Python as administrator.
  • Windows 에서 심링크 권한이 없어 HF 캐시가 복사 모드로 동작. 기능은 정상, 디스크만 더 쓴다(모델 ~1.6GB 가 blobs+snapshots 로 중복 → 약 2배).
목적조치
디스크 절약Windows 개발자 모드 켜기(설정 → 개발자용) 또는 관리자로 실행 → 심링크 사용
경고만 끄기환경변수 HF_HUB_DISABLE_SYMLINKS_WARNING=1
그냥 두기무방 — 디스크 조금 더 쓰는 정도

5. 곁가지 — TLS 가로채기 대응이 전사에도 적용됨

HF 모델 다운로드가 CERTIFICATE_VERIFY_FAILED 없이 진행된 것 = 앞서 base 의존성에 추가한 pip_system_certs 가 venv 의 모든 Python 프로세스(yt-dlp 서브프로세스뿐 아니라 transcribe CLI/서버, 그리고 HuggingFace·Claude·OpenAI 호출까지)에 OS 신뢰 저장소를 적용하기 때문이다. 가로채기 환경 대응이 전사 경로에도 공짜로 먹은 셈.

자세한 배경: docs/implement/tls_ytdlp_cert_260621.html.

주의(잠재): 이번에 numpy 2.5.0 이 들어왔다. 나중에 화자 구분(diarize) 실행 시 torch 가 compiled against numpy 1.x 류 에러를 내면 torch/numpy 버전을 맞춰야 한다(지금 전사에는 영향 없음).
