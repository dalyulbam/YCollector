§1무엇이 문제였나 — Before / After

YCollector 에는 두 세계가 따로 있었습니다. 웹 보드(다운로드·영상 생성)와 CLI 파이프라인(전사·요약·앨범)이 서로를 전혀 모르는 상태였죠. 그래서 download/LJM 에서 만든 9권의 분석 결과가 보드에는 보이지 않았습니다.

❌ Before — 두 세계가 단절

[브라우저 보드 :8765] ├─ ① YouTube 다운로드 ✔ ├─ ② 영상 생성(Sora) ✔ └─ ③ 작업 목록 ✔ (전사·요약 없음) [터미널 CLI] 연결 ycollector-transcribe ←── 없음 ycollector-analyze ycollector-album └→ download/LJM/_analysis, _album (파일 탐색기로만 열람)

✅ After — 보드가 파이프라인을 품음

[브라우저 보드 :8765] ├─ ① YouTube 다운로드 ├─ ② 영상 생성(Sora) ├─ ③ 전사·요약 분석 보드 ★새것 │ ├ 폴더/파일 스캔 + 체크박스 │ ├ [선택 N개 분석] 버튼 │ ├ 요약·대본 뷰어(모달) │ └ 앨범 보기/생성 버튼 └─ ④ 작업 목록 (분석 진행률도 표시) 서버가 CLI 와 같은 파이썬 모듈을 직접 호출 — 코드 중복 0

핵심 아이디어

CLI 명령을 서버가 subprocess 로 실행하는 게 아니라, CLI 가 쓰는 같은 파이썬 함수(TranscribeEngine, Summarizer, write_reports, album.main)를 서버 워커가 직접 import 해서 호출합니다. 로직은 한 곳(transcribe 모듈)에만 있고, CLI 와 웹은 둘 다 그걸 부르는 "껍데기(인터페이스)"일 뿐입니다.

§2용어 정의 — 최소 사전

용어뜻 (이 프로젝트 기준)
API프로그램끼리 대화하는 약속된 창구. 여기서는 "브라우저(JS)가 서버(Python)에 일을 시키는 URL 목록".
엔드포인트API 의 개별 주소 1개. 예: POST /api/analyze. "메서드 + 경로"의 조합.
GET / POSTHTTP 메서드. GET = "읽기"(조회), POST = "쓰기/실행"(작업 시작, 설정 저장).
FastAPIPython 웹 프레임워크. 함수 위에 @app.get("/경로") 데코레이터를 붙이면 그 함수가 해당 URL 의 처리기가 됨.
라우트(route)"이 URL 이 오면 이 함수를 실행하라"는 연결. 위 데코레이터 한 줄이 라우트 등록.
JSON브라우저↔서버가 주고받는 데이터 표기법. {"root": "dl", "files": [...]} 형태.
잡(Job)오래 걸리는 작업 1건(다운로드 1건, 분석 1건…). 서버는 잡마다 _JobRow 객체 1개를 만들어 상태를 기록.
워커 스레드잡의 실제 일(전사 등)을 수행하는 별도 실행 흐름. 메인 서버는 응답만 빨리 돌려주고, 무거운 일은 스레드에 맡김.
블로킹(blocking)끝날 때까지 다른 일을 못 하게 막는 호출. faster-whisper 전사는 블로킹이라 메인 서버에서 직접 돌리면 보드 전체가 멈춤 → 그래서 스레드.
SSE
(Server-Sent Events)		서버→브라우저 단방향 실시간 푸시. 브라우저가 연결을 열어두면 서버가 "진행률 37%" 같은 이벤트를 계속 흘려보냄. 양방향인 WebSocket 보다 단순.
EventSourceSSE 를 받는 브라우저 내장 객체. new EventSource(url) 한 줄이면 끝.
전사(transcribe)음성 → 텍스트 변환. 여기서는 faster-whisper(Whisper 모델의 고속 구현)가 로컬에서 수행. 무료, 인터넷 불필요(모델 캐시 후).
faster-whisperOpenAI Whisper 를 CTranslate2 엔진으로 다시 구현한 라이브러리. GPU(CUDA) 또는 CPU(int8 양자화)로 추론.
요약(summarize)전사록 → 전체 요약 + 핵심 포인트 + 시간대별 핵심 파트. Anthropic Claude API 호출(유료, ANTHROPIC_API_KEY 필요, 예산 상한 지정 가능).
앨범(album)요약의 핵심 파트마다 ffmpeg 로 영상 프레임을 캡쳐해 만든 HTML 화보집. _album/index.html.
정적 파일 서빙서버가 디스크의 파일(html, jpg, md…)을 그대로 돌려주는 것. 새 라우트 /files/... 가 담당.
경로 탈출
(path traversal)		../../비밀파일 처럼 허용된 폴더 밖의 파일을 빼가는 공격. §7 에서 차단 방법 설명.
CORS다른 사이트의 JS 가 우리 서버를 호출해도 되는지 정하는 브라우저 규칙. 이 서버는 *(전부 허용)라 경로 검증이 더 중요해짐.

§4동작 원리 — 분석 1건이 흐르는 길

"체크박스 2개 선택 → 선택 2개 분석 클릭" 했을 때 일어나는 일을 시간 순서대로 따라갑니다. 위치 표시: BROWSER = 브라우저의 JS(app.js), SERVER = FastAPI 메인(이벤트 루프), WORKER = 분석 전용 스레드.

1
BROWSER선택 수집 + 폴더별 묶기

anSel(Map)에 담긴 선택을 root|폴더 단위로 묶는다. 같은 폴더의 파일들은 잡 1개로 — 산출물이 같은 _analysis/ 에 모이기 때문.

▼ fetch POST /api/analyze {root, files, language, summarize, budget_usd}
2
SERVER검증 → 잡 등록 → 스레드 시작 → 즉시 응답

경로 검증(_safe_join) 통과한 파일 목록으로 _JobRow(jid, "analyze", …) 를 만들어 _state.jobs 에 넣고, threading.Thread(target=_run_analyze…).start(). 그리고 바로 {"job_id": "a1b2c3…"} 응답. 전사가 끝나길 기다리지 않는다(논블로킹).

▼ 응답 받은 즉시 new EventSource("/api/jobs/{id}/events")
3
BROWSER작업 목록에 카드 생성 + SSE 구독

trackJob() 이 패널 ④에 진행률 카드를 만들고 SSE 연결을 연다. 서버는 연결 직후 현재 상태 스냅샷 1건을 먼저 보낸다.

▼ 그 사이 워커 스레드는 이미 일하는 중
4
WORKER모델 로드 → 파일별 [전사 → 요약 → 리포트]

① TranscribeEngine 생성(Whisper 모델 로드, 최초엔 다운로드). ② 파일마다 전사 — 세그먼트가 나올 때마다 콜백이 진행률을 계산(초당 1회로 제한). ③ 요약이 켜져 있으면 Summarizer.summarize() 가 Claude 호출(예산 사전 점검). ④ write_transcript(.srt) + write_reports(.script.md/.summary.md) 저장.

▼ job.emit_sync("progress", progress=0.37, message="[1/2] 전사 43% · …")
5
SERVERemit_sync — 스레드의 소식을 SSE 로 중계

워커는 별도 스레드라 asyncio 큐에 직접 못 넣는다. emit_sync 가 loop.call_soon_threadsafe(q.put_nowait, msg) 로 "메인 이벤트 루프야, 네 차례 될 때 이 메시지 큐에 넣어줘"라고 안전하게 부탁한다. 큐에 들어간 메시지는 열려 있는 SSE 연결로 흘러나간다.

▼ data: {"event":"progress","progress":0.37,…}\n\n
6
BROWSER카드 실시간 갱신

es.onmessage 가 이벤트 종류별로 분기: progress → 진행 바 폭, status → 상태 태그, estimate → 누적 비용, error → 빨간 에러 줄.

▼ 마지막 파일까지 끝나면 emit_sync("done", out_path=…)
7
BROWSERdone → 분석 보드 자동 새로고침

카드가 ✓ done 으로 바뀌고, loadAnalysisBoard() 를 다시 불러 방금 생긴 요약·대본 버튼이 보드에 나타난다. "요약" 클릭 → /files/... 로 .md 를 받아 모달에 렌더.

왜 "즉시 응답 + SSE" 인가? (폴링과 비교)

전사는 몇 분씩 걸립니다. 응답을 끝까지 기다리게 하면 브라우저는 타임아웃, 서버는 그동안 다른 요청 처리 불가. 그래서 ① 접수증(job_id)만 먼저 주고 ② 진행 상황은 SSE 로 흘려보냅니다. 브라우저가 1초마다 "끝났어요?"라고 묻는 폴링보다 트래픽이 적고 반응이 즉각적입니다. 이 구조는 다운로드·Sora 생성이 이미 쓰던 것 — 분석은 같은 레일에 올라탔을 뿐입니다.

§5새 API 4개 레퍼런스

GET /api/analysis/overview — 보드에 뿌릴 현황 스캔

다운로드 루트들을 훑어 "어떤 영상이 있고, 무엇이 이미 분석됐고, 앨범이 있는지"를 돌려줍니다. 보드가 처음 뜰 때·새로고침 때·잡 완료 때 호출. 

// 응답 예시 (요약)
{
  "roots": [
    { "key": "out", "path": "D:\\26y\\YCollector\\downloads", "folders": [ … ] },
    { "key": "dl",  "path": "D:\\26y\\YCollector\\download",
      "folders": [
        { "name": "LJM", "rel": "LJM",
          "analyzed": 9,                          // 9개 중
          "items": [
            { "name": "….webm", "rel": "LJM/….webm", "bytes": 123456789,
              "summary": "LJM/_analysis/….summary.md",   // null 이면 미분석
              "script":  "LJM/_analysis/….script.md" }, …
          ],
          "album": "LJM/_album/index.html",
          "standalones": ["LJM/LJM_album_standalone.html"] }
      ] }
  ]
}

POST /api/analyze — 전사(+요약) 잡 시작

// 요청
{ "root": "dl",                       // overview 가 준 루트 키
  "files": ["LJM/영상1.webm", …],      // 루트 기준 상대 경로
  "language": "ko",                   // "auto" = 자동 감지
  "summarize": true,                  // false = 전사+대본만(무료)
  "budget_usd": 5 }                   // Claude 비용 상한
// 응답
{ "job_id": "d9c114c07c8e" }

산출물은 각 영상 폴더의 _analysis/에: <파일명>.srt(타임스탬프 전사), .script.md(대본), .summary.md(요약 — 요약 켰을 때).

POST /api/album — 장면 앨범북 생성 잡 시작

// 요청
{ "root": "dl", "dir": "LJM", "frames": 3 }   // frames = 장면당 캡쳐 수(1~6)
// 응답
{ "job_id": "…" }      // _analysis/*.summary.md 가 없으면 400

GET /files/{root}/{경로} — 산출물·앨범·영상 서빙

GET /files/dl/LJM/_album/index.html          → 앨범 (상대 링크 그대로 동작)
GET /files/dl/LJM/_analysis/….summary.md     → 요약 원문 (UTF-8 text)
GET /files/dl/LJM/….webm                     → 영상 (브라우저 재생 가능)

URL 구조가 실제 폴더 구조를 그대로 비추기 때문에, 앨범 HTML 안의 book01/index.html 같은 상대 링크가 수정 없이 동작합니다. 이것이 ?path=… 쿼리 방식 대신 경로 방식을 고른 이유입니다. 서빙은 확장자 화이트리스트(미디어 + html/md/srt/vtt/txt/json/이미지)로 제한됩니다 — 다운로드 폴더에 우연히 섞인 무관한 파일은 404.

§6변수·필드 정의

서버 (server.py)

이름정의
_ANALYSIS_DIRNAME = "_analysis"분석 산출물 폴더 이름. 영상 폴더 바로 아래 생성. CLI 와 동일 규약.
_ALBUM_DIRNAME = "_album"앨범 출력 폴더 이름.
_media_roots()스캔/서빙이 허용된 루트 폴더 목록 [(키, 절대경로)]. 키: out = settings.ini 의 output_dir, dl/dls = 서버 실행 폴더의 download/downloads. 존재하는 것만, 중복 경로는 1개만.
_safe_join(root, rel)루트 안에서만 경로를 합치는 보안 함수. 탈출 시도면 None. §7 참고.
_scan_overview()루트 직속 + 1단계 하위 폴더의 미디어/산출물 현황 수집. _·. 으로 시작하는 폴더는 건너뜀(_analysis 자신을 스캔하지 않도록).
_JobRow.kind잡 종류: "download" | "generate" | "analyze" | "album". 보드 카드의 라벨 색을 결정.

_JobRow.progress0.0~1.0. 보드 진행 바의 폭.

_JobRow.eventsSSE 구독자별 asyncio 큐 목록. 같은 잡을 여러 탭이 봐도 각자 큐를 가짐.
t_share (워커 지역변수)파일 1개 진행률에서 전사가 차지하는 비중. 요약 ON 이면 0.85(전사 85% + 요약 15%), OFF 면 1.0. 전사가 압도적으로 오래 걸리는 현실을 반영한 가중치.
on_seg(seg, duration)세그먼트 1개가 나올 때마다 불리는 콜백. 진행률 = (현재파일번호 + 파일내비율×t_share) / 전체파일수. 초당 1회만 emit(SSE 폭주 방지).
budget_usd요약 예산 상한. Budget.precheck() 가 호출 전 예상 비용으로 초과를 차단 — "끝나고 보니 과금 폭탄"을 구조적으로 방지.

§7보안 — 경로 탈출은 왜, 어떻게 막았나

/files/{root}/{경로} 는 "디스크의 파일을 돌려주는" 라우트입니다. 검증 없이 만들면 /files/dl/../../.env 로 API 키가 든 파일을 빼갈 수 있습니다. 게다가 이 서버는 CORS 가 * 라서, 사용자가 열어둔 악성 웹페이지의 JS 도 http://127.0.0.1:8765 를 호출할 수 있습니다. "로컬 전용이니까 안전"이 성립하지 않는 이유입니다. 

def _safe_join(root: Path, rel: str) -> Path | None:
    # ① 빈 경로 / 절대경로(\로 시작) / 콜론(드라이브 문자 C:, NTFS ADS) 거부
    if not rel or rel.startswith(("/", "\\")) or ":" in rel:
        return None
    try:
        # ② 합친 뒤 resolve() — "..", 심볼릭 링크까지 실제 경로로 펼침
        target = (root / rel).resolve()
        # ③ 펼친 결과가 여전히 root 아래인지 최종 확인
        if not target.is_relative_to(root):
            return None
    except (OSError, ValueError):
        return None
    return target
공격 입력차단 지점
../pyproject.toml③ — resolve 후 루트 밖
LJM/../../settings.ini③ — 중간에 끼워도 resolve 가 펼침
C:/Windows/win.ini① — 콜론 거부
/etc/passwd, \\서버\공유① — 절대경로 거부
file.txt:hidden (NTFS 대체 스트림)① — 콜론 거부
URL 인코딩 %2e%2e%2fFastAPI 가 디코드한 뒤 들어오므로 위와 동일하게 ③
화이트리스트 외 확장자 (.bin, .exe …)라우트의 확장자 검사 — 존재 여부도 숨기려 404 로 응답

같은 원칙이 POST /api/analyze 에도 적용됩니다: 경로 검증(_safe_join) + 미디어 확장자만 허용 + 모델 이름 형식 검사(영숫자·._/- 만). "서버가 받는 모든 입력은 악의적일 수 있다"고 가정하고 입구에서 거릅니다.

원칙: 허용 목록(allow-list) 사고방식

"위험한 패턴을 골라 거부"(.. 금지 등)가 아니라 "루트 안에 있음이 증명된 경로만 허용"으로 뒤집는 것이 안전합니다. ①은 빠른 사전 거부, ③(resolve 후 포함 확인)이 실질적 안전망 — 새로운 우회 기법이 나와도 ③에서 걸립니다. 같은 함수를 /api/analyze·/api/album 의 입력 검증에도 재사용해 검증 로직이 한 곳에만 존재합니다.

§9설계 결정 노트 — 왜 이렇게 만들었나

결정이유
CLI 모듈을 직접 import (subprocess 아님) 진행률 콜백(on_segment)을 함수 인자로 바로 받을 수 있어 SSE 연동이 자연스럽다. subprocess 였다면 stdout 파싱이라는 깨지기 쉬운 다리가 필요했다. 예외도 파이썬 객체로 그대로 받아 카테고리별 친절한 에러(not-installed 등)를 유지.
기존 잡/SSE 인프라에 그대로 편승 _JobRow·emit_sync·/api/jobs/*·trackJob 을 한 줄도 복제하지 않았다. 새 작업 종류는 kind 문자열 2개("analyze", "album")가 전부. 인프라가 한 벌이면 버그 수정도 한 곳에서 끝난다.
루트를 키("out"/"dl"/"dls")로 추상화 설정의 downloads 와 과거 산출물의 download(LJM)가 공존하는 현실 수용. 절대 경로를 URL 에 노출하지 않고, 서빙 허용 범위를 이 목록으로 한정하는 보안 경계도 겸한다.
분석 요청을 폴더 단위 1잡으로 묶기 같은 폴더 파일들은 같은 _analysis/ 에 쌓이고, Whisper 모델 로드(수십 초)를 잡 1개당 1번만 치른다. 파일마다 잡을 쪼개면 모델을 N 번 로드한다.
markdown 렌더러를 30줄 자작 이 webui 는 "빌드 없음·의존성 없음"이 원칙. 입력이 우리가 직접 생성하는 summary.md/script.md 뿐이라 패턴이 6개로 고정 — 범용 라이브러리는 과잉. 단, 이스케이프를 먼저 하고 치환은 나중에(XSS 순서) 라는 원칙은 그대로 적용.
진행률 가중치 t_share = 0.85 진행 바가 "전사 끝났는데 95%에서 한참 멈춤"이 되지 않도록, 요약 구간에 15%를 남겨두는 UX 보정. 정밀 측정값이 아니라 체감 보정값이다.
앨범은 album.main() 호출로 끝 앨범 생성은 진행률을 세분화할 가치가 낮은 일괄 작업(수십 초~수 분). CLI 의 main 을 그대로 불러 인자만 서버가 채운다 — 코드 0줄 복제.
SSE emit 을 초당 1회로 제한 Whisper 는 세그먼트를 초당 수십 개 뱉을 수 있다. 그대로 흘리면 SSE 큐·브라우저 렌더가 낭비된다. 진행률은 사람이 보는 것 — 1Hz 면 충분하다.
